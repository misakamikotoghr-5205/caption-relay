## One quality iteration

The `get_cue` tool now returns the original cue, its own heuristic issues, and
optional literal glossary replacements. **Those candidates are generated by
the program, not by the model.** They are clearly labeled data, are not applied
automatically, and are not the only values permitted by the model schema. The
model may decline them. The instruction asks for exact target capitalization,
preservation of facts and meaning, and an empty proposal array when no edit is
needed. These instructions are not a proof of semantic correctness.

Exactly one new production probe was then run on 2026-11-09:
[run 5](local-model-20261109-5.json). It used the actual production HTTP adapter,
with a logging wrapper only, and the official `qwen2.5:0.5b` tag. The recorded
installed model is Q4_K_M; it must not be described as Q8. No model was downloaded
for this iteration. Start: 07:35:09.831 UTC; recorded completion:
07:35:40.367 UTC; measured review duration: 30.503 seconds; process exit: 0.

The three real responses selected `get_cue` for cue 1, `get_cue` for cue 2,
then `propose`. The final proposal's text was exactly:

> caption relay

Its source text was `Welcome to caption relay.`. The model's reason mentioned
the desired `Caption Relay` terminology, but the proposed text omitted the
opening words and did not use that capitalization. The proposal passed only
structural/ID/capability validation. **A human should retain the original and
reject this proposal.** Do not call it a successful correction or silently
substitute the program-generated candidate for the actual model response.

The probe confirms a real bounded read-tool/proposal workflow and unchanged
source input/timing. It does not establish useful general editing quality,
audio alignment, transcription accuracy, hosted inference or UI execution.
No further model requests were made for this iteration. All raw responses are
preserved in the linked JSON records.

## Verification and limits

The current source passed 22 backend tests and the dedicated strict TypeScript
check documented in `../backend-verification.md`. The three added regressions
cover valid no-op filtering, scoped candidate data without automatic adoption,
and literal regex/replacement text. These use explicitly mocked model replies,
separately from the real production probe.

Production configuration remains nominally 120,000 ms per request and 360,000 ms
per review, three model turns, one concurrent review, and 10-minute keep-alive.

advertised as strict wall-clock guarantees. No permissions, tool capabilities,
timing guards or paid service boundaries were relaxed for this iteration.
