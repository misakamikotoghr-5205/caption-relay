# 字幕交接台 Caption Relay｜MINMAX 商业计划书

版本：2026-11-09。个人开发的可运行原型；以下区分已验证行为与后续商业假设。正式投稿、发件与组委会收件分别记录。

## 第1页｜把修改依据一起交出去

**字幕交接台 Caption Relay：面向短视频创作者与小型制作团队的字幕交接工具。**

导入 SRT/VTT，定位时间重叠、阅读负担与术语差异；程序生成保留其余原文的术语候选，本地 AI 判断是否建议采用并解释理由，作者逐句确认，最后导出字幕与交接记录。

作者：**Hengrui Guo，个人开发者，团队一人。** 项目于 2026-11-09 新建，使用多智能体辅助编码、独立复核与文档制作。没有虚构成员、客户或主办方背书。联系信息仅用于正式报名与投稿邮件。

## 第2页｜问题：改完文字，还没完成交付

字幕交接涉及三个不同问题：相邻片段是否重叠，给定时间是否足以阅读，同一名称是否前后一致。把文字改得流畅，不能自动解决时间轴问题；自动覆盖整句，也可能损失原意。

目标场景是短视频字幕从创作者交给剪辑或审校同事之前的一次检查。需要交出的不只是最终文本，还包括修改理由、未处理问题及人工决定。

当前目标用户与付费意愿属于待访谈假设，尚无客户、收入或节时比例。原型先验证一个较窄的流程：检查、受约束术语审校和有记录的交接；语音识别、翻译与完整视频编辑不在当前范围内。

## 第3页｜方案：候选有边界，决定可回看

1. 导入普通 SRT/VTT，解析毫秒时间码与字幕原文。
2. 程序检查重叠、速率、行长、间隔与术语，显示可定位的编辑提示。
3. 按用户词表生成逐词替换候选，保留其余文字与起止时间。
4. 真实本地模型调用只读工具，检查上下文，选择“建议”或“保留”并给出理由。
5. 作者逐句确认；未采用的字幕保持原样，最后导出字幕和审计 JSON。

模型不能自由写入字幕或修改时间轴。程序候选与模型判断分别记录来源。时间问题由作者回到剪辑软件处理，规则命中本身不等于字幕一定错误。

## 第4页｜实测证据与可复现演示

后端已有 **28 项行为测试**与严格 TypeScript 检查通过，覆盖格式保真、重叠边界、Unicode 计数、候选选择、恶意输出拒绝、限流及失败处理。网页已实际验证导入五句中文字幕和显示三项检查提示。

采用 Ollama 0.40.15 与真实 qwen2.5:0.5b（Q4_K_M，约 398 MB）进行原创虚构案例实跑。候选选择版本实际三轮、63.690 秒：模型读取第一条，选择程序候选，完整文本为“Welcome to Caption Relay.”。第二条未被审阅；不把本次小样当作全文件覆盖或质量基准。

原型保留此前超时、无变化提案及删词失败的原始记录。删词问题推动了当前候选选择权限设计。实际网页 HTTP 接口返回 200，并连接本地模型给出第二句术语建议；另一步显式接受第二句，导出了 SRT、VTT 与审计 JSON，首句保留、时间码未变。完整浏览器人审导出尚未验证；不将 HTTP 和命令行实跑冒称浏览器全程操作。

## 第5页｜技术：把能力限制写进程序

| 环节 | 程序职责 | 模型与人工职责 |
| --- | --- | --- |
| 输入与检查 | 解析支持的字幕子集；计算时间、速率与词表命中 | 模型不决定解析是否成功；人判断规则是否适用 |
| 候选生成 | 仅生成词表字面替换，保留其他文字与时间 | 候选由程序生成，不冒称模型自由创作 |
| Agent 选择 | 只读工具返回实际原句、检查项和候选；验证已读取的候选 ID | 模型选择建议或保留并说明理由；不能传替换文本、执行命令或访问任意网址 |
| 人审与导出 | 根据明确采用决定导出原文、现文、问题和记录 | 人保留最终决定；未采用项不修改 |

模型请求固定本机回环地址，不要求 API key。没有连接模型时明确返回仅规则检查，不编造 AI 建议。本机模型不等于远端托管也具备模型能力。

## 第6页｜竞品与开源来源

成熟工具 Subtitle Edit 覆盖完整字幕编辑、同步、翻译和纠错，功能范围明显更广。Caption Relay 聚焦一个较窄的交接环节：把可定位规则、程序候选、AI 选择与人工决定放入同一份输出。它不宣称首创或替代完整字幕编辑器。

Subtitle Edit 仅用于比较，没有复制其源码。来源与许可：https://github.com/SubtitleEdit/subtitleedit 。实际框架包括 Sites Vinext starter、React/Next.js、Vinext/Vite、Tailwind CSS 与 Lucide；具体版本在 package-lock.json，保留了 vendor 许可文件。

Ollama 与 Qwen2.5 是外部运行时和模型依赖；仓库不分发模型权重。项目原创代码采用 MIT 许可。运行时与模型来源：https://github.com/ollama/ollama 、https://huggingface.co/Qwen/Qwen2.5-0.5B-Instruct 。复用范围和完整证据以源码及文档为准。

## 第7页｜价值与商业假设

拟验证的价值是：审校者能否更快定位待处理字幕，能否区分规则事实与模型意见，接手者能否从交接包理解每次修订。当前不声称已证明效率提升。

先以免费本地原型验证单人交接；潜在后续模式是团队术语模板、批量检查和协作交接记录。价格、转化率、云推理成本与维护成本仍需测试，当前无支付流程，也不要求参赛评委购买额度。

拟访谈少量创作者及剪辑人员，在取得同意后记录完成时间、误报、漏报、采用与拒绝原因。将公开样本规模、指标分母及失败，不把合成案例当作真实客户效果。

## 第8页｜试用方式与下一步

评委可按 README 在本地运行：安装 Node.js 22.13+ 和依赖，启动 Ollama 并下载官方 qwen2.5:0.5b，再启动网页。无需测试账号、卡片或付费订阅。原创字幕、模型实跑记录及本地运行说明随源码提供；本地例外依据官方 Q8。

下一步优先验证更多词表语境、未审阅项提示与不同语言的误报；之后再评估团队共享及更强模型。模型仍可能判断错误或不返回建议；时间码检查不是音频对齐或无障碍认证。
